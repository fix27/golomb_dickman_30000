# Проверка сертификата на 40 000 знаков

Этот файл описывает, **что именно** проверяется, **чем** и **какие
результаты** получены. Цифры сертификата не меняются: проверка либо
подтверждает их, либо сообщает о расхождении.

## Коротко

| Уровень | Инструмент | Что проверяет | Время |
|---|---|---|---|
| 1. Артефакты | `verify_40000.py` | сертификат, файл цифр, b-file | секунды |
| 2. Чекпоинты | `verify_checkpoints.py` | все 1 209 чанков: структура, покрытие, точные суммы | ~1 мин |
| 3. Константы | `verify_nodes_decimal.py --plan` | $B_{\rm disc}$, $\tau_R$, $\tau_L$ заново | минуты |
| 4. Узлы (без Arb) | `verify_nodes_decimal.py` | суммы выбранных чанков заново, 100 знаков | ~1 мин |
| 5. Узлы (Arb) | `verify_checkpoints_arb.py --all` | все узлы в шаровой арифметике | часы |

Уровни 1–4 выполнены на этом комплекте и **прошли**. Уровень 5 требует
`python-flint`; он реализован, но на машине, где готовился комплект, не
запускался (см. «Ограничения»).

## Уровень 1. Артефакты

```bash
python verify_40000.py
```

Проверки: интервал $[\Lambda_-,\Lambda_+]$ не пересекает границу десятичной
ячейки; цифры сертификата равны $\lfloor 10^{40000}\Lambda_\pm\rfloor$;
отдельный файл цифр совпадает с сертификатом; b-file содержит ровно 40 000
термов $n=0..39999$, только ASCII/LF, без BOM и табов, каждая цифра
совпадает с сертификатом; первые 102 цифры совпадают с OEIS A084945.

## Уровень 2. Все 1 209 чанков

```bash
python verify_checkpoints.py
```

Скрипт **не доверяет** сохранённым значениям как доказательству, но и не
пересчитывает Arb-шары: он проверяет внутреннюю согласованность набора.

1. `meta.pkl` разбирается безопасным unpickler'ом (импорт классов запрещён) и
   сверяется с формулами плана: `D`, `G`, `Ebits`, `h` (двоично-рациональное),
   `K_L`, `K_R`, `chunk`.
2. Все файлы `c_*.pkl` присутствуют, разбираются, диапазоны $[lo, hi)$
   совпадают с ожидаемыми и покрывают $[-K_L, K_R+1)$ ровно один раз.
3. Каждый интервал удовлетворяет $L \le H$ и разумной оценке ширины.
4. Точные целые суммы `Lsum`/`Hsum` пересчитываются заново; из них и поправок
   $B$, $TR+TL+B$ получаются ровно те концы, что записаны в сертификате.
5. $B \ge 0$, $TR+TL+B \ge B$, интервал не пересекает десятичную границу,
   цифры и b-file совпадают, первые 102 цифры — с OEIS.

Фактический результат:

## Уровень 3. Ошибка дискретизации и хвосты

```bash
python verify_nodes_decimal.py --plan
```

Константы пересчитываются заново по формулам из `golomb_dickman.py`
(лемма 4 для $M$, правило трапеций для $B_{\rm disc}$, лемма 3 для хвостов),
но на `decimal` вместо Arb. Результат:

```text
  log10 M      = 360.3909
  log10 B_disc = -41285.4628   (requirement 10^-40036)
  log10 tau_R  = -40045.8435
  log10 tau_L  = -40045.6719
  B  = 1
  TR = 26431841856436
  TL = 39242142865260
  TR + TL + B = 65673984721697
  certificate implies B = 1, TR + TL + B = 65673984721697
OK: discretisation and tail bounds reproduce the certificate corrections
```

То есть поправки не «подогнаны»: они получаются из независимо посчитанных
$B_{\rm disc}$, $\tau_R$, $\tau_L$ с точностью до целого. Запас по
дискретизации — около 1249 порядков ($10^{-41285.46}$ против требуемых
$10^{-40036}$).

## Уровень 4. Пересчёт сумм узлов без Arb

```bash
python verify_nodes_decimal.py --chunks 20 --decimals 100
```

Для выбранных чанков заново суммируется

$$G(kh)=e^\gamma u^2\left(1+e^{-t}\right)e^{-2u+S},\qquad
u=e^{t-e^{-t}},\quad S=\sum_{j\ge2}\frac{(-u)^j}{j\,j!},\quad t=kh,$$

где $\gamma$ взята из OEIS A001620. Сумма сравнивается с сохранённым
интервалом в целых числах: проверяется, что первые 100 десятичных знаков
$\sum G$ совпадают с теми, которые фиксирует сохранённый интервал.

Дополнительно `--methods` сверяет три независимые формулы для $E_1$
(ряд, цепная дробь Стилтьеса, асимптотика); на сетке $u\in[0.1,20000]$
они совпадают до 30–70 знаков.

Это **численная согласованность, а не доказательство**: 100 знаков вместо
40 042. Смысл — поймать систематическую ошибку в формулах, индексации или
в сохранённых суммах на машине без Arb.

## Уровень 5. Полный пересчёт в Arb

```bash
python -m pip install python-flint
python verify_checkpoints_arb.py --audit          # константы и поправки
python verify_checkpoints_arb.py --sample 20      # выборочно, ~минуты
python verify_checkpoints_arb.py --all --jobs 8   # все 1 209 чанков, часы
```

Скрипт не импортирует `golomb_dickman.py`. Он независимо реализует ряд,
цепную дробь Стилтьеса и асимптотику для $E_1$, заново считает
$M$, $B_{\rm disc}$, $\tau_R$, $\tau_L$, пересчитывает шары узлов, проверяет,
что каждый пересчитанный интервал лежит внутри сохранённого, и что итоговый
интервал доказывает ровно опубликованные 40 000 цифр.

Результаты кэшируются в `%LOCALAPPDATA%\gd_verify_cache\D40000` (вне
репозитория), поэтому `--all` можно прерывать и продолжать.

## База доверия

Проверка условна по отношению к:

1. корректности Arb (`python-flint`) — уровни 5 и частично 3;
2. корректности `decimal` (libmpdec) — уровни 3 и 4;
3. теореме о трапециях (Trefethen & Weideman, *SIAM Review* 56 (2014), Thm 5.1);
4. теореме Стилтьеса о двусторонних оценках подходящими дробями;
5. элементарным леммам 1–7 из docstring `golomb_dickman.py`;
6. точной целочисленной арифметике Python.

Это не формализация в proof assistant.

## Ограничения

- Уровень 5 не запускался на машине, где собран комплект: политика
  Application Control блокирует загрузку DLL `libflint`/`libgmp`. Скрипт
  проверен на синтаксис и логику, но не исполнялся с Arb.
- Уровень 4 проверяет выбранные чанки, а не все 1 209, и только 100 знаков.
- Проверка не заменяет повторный прогон `golomb_dickman.py`: она проверяет
  **результат**, а не воспроизводит вычисление тем же кодом.

## Найденные и исправленные дефекты

Исходная рабочая копия имела дефекты формата и гигиены. **Ни одно число не
изменено**: для каждого файла проверено, что после удаления символов CR
байтовое содержимое совпадает с исходным.

| # | Дефект | Файл | Исправление |
|---|---|---|---|
| R1 | CRLF во всех 40 001 строках | `b084945.txt` | CRLF → LF, 348 892 → 308 891 B |
| R2 | 4 изолированных CR (смешанные переводы строк) | `golomb_dickman_40000_certified.txt` | CR удалены, 120 261 → 120 257 B |
| R3 | завершающий CR | `golomb_dickman_40000_digits.txt` | 40 002 → 40 001 B |
| R4 | 849 CR | `golomb_dickman.py` | 59 448 → 58 599 B |
| R5 | 4 CR | `smoke_60.txt` | 435 → 431 B |
| R6 | 156 CR | `verify_40000.py` | 5 552 → 5 396 B |
| R7 | 107 и 146 CR | `OEIS_SUBMISSION.md`, `PUBLICATION_CHECKLIST.md` | CRLF → LF |
| R8 | `SHA256SUMS.txt` внутренне противоречив: хеши `b084945.txt`, файла цифр и `golomb_dickman.py` были посчитаны для LF-версий, а сертификата и `smoke_60.txt` — для CRLF-версий, поэтому `sha256sum -c` падал на 3 файлах из 5 | `SHA256SUMS.txt` | пересчитан по всем файлам в канонической форме |
| R9 | ширина интервала указана как $10^{-40042.4}$ | `README.md` | $10^{-40042.26}$ (как в сертификате) |
| R10 | в комплекте лежал `__pycache__/golomb_dickman.cpython-314.pyc` (68 KB) | — | удалён, добавлен `.gitignore` |
| R11 | ширина интервала печаталась как $10^{-40042.4}$: оценка $\log_2$ бралась по `bit_length() - 1`, что занижает логарифм на величину до 0.30 | `verify_40000.py` | используется `math.log2()`, печатает $10^{-40042.3}$ |

R9 и R11 — одна и та же ошибка: README цитировал вывод скрипта, а скрипт
занижал ширину на 0.14 порядка. На сертификат это не влияло: он хранит точные
целые концы, а не приблизительную ширину.

Именно R1 и был виден как `FAIL: b-file contains CR characters; OEIS expects
plain ASCII with LF`. Проверяющий скрипт был прав: дефект в файле, а не в
цифрах.

## Контрольные суммы

Каноническая форма всех текстовых артефактов — UTF-8/ASCII с переводами
строк LF и без BOM. Проверка:

```bash
sha256sum -c SHA256SUMS.txt        # Linux/macOS/Git Bash
Get-FileHash * -Algorithm SHA256   # Windows PowerShell
```

Файл `.gitattributes` фиксирует LF для текстовых файлов и `binary` для
`*.pkl`, чтобы контрольные суммы не зависели от `core.autocrlf`.
`SHA256SUMS.txt` содержит 15 записей; сам файл контрольных сумм в список не
входит.
